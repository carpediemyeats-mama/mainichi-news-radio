# ことば幻獣ラジオ｜シリーズ制作・子ども試聴基準 v1

作成日: 2026-10-28
適用対象: 「ことば幻獣ラジオ」第2回以降の全台本・音声制作
基準回: 第1回「消えた宝箱！犯人は誰だ？」（完成MP3 12分05秒、10語、6章、4声、考える間つき6問）

## 最優先の約束

毎回「第1回と同等以上に楽しめる完成品」をめざす。ただし、事件・展開・笑い・舞台・学ぶ語彙は変化させ、同じ型の単純な繰り返しにはしない。

**台本の完成と音声の完成の間に、必ず一度立ち止まり、小4・小6の子どもが画面を見ず、耳だけで理解し、考え、最後まで聴きたくなるかを編集者が点検する。** 機械的な文字数チェックだけを合格判定にしない。

## 1. 企画・台本の必須要件

- 一話完結を基本に、次回も楽しみになる世界観。前回未聴でも入れる。
- 冒頭30〜60秒以内に「何が起きた？」「どうなる？」を提示。導入説明が長い場合は書き直す。
- 小4が面白く聴け、小6にも幼稚すぎない物語・推理・気持ちの読み取り。子どもを見下した言い回しにしない。
- ユーザー提供の729語マスターに実在する語を選ぶ。IDと表記を保ち、意味は適切に検証する。原典に意味・例文がない場合は番組用の新規解説と明示。
- 1回の新規語彙は基本8〜10語（話の自然さを優先して調整）。新語を一気に列挙せず、物語の必要な場面で使う。
- 主要語は「自然な会話で使用→文脈から意味を推測→短い解説→別場面で再登場」という順を意識する。少なくとも2回の文脈使用。
- 語彙そのものだけでなく、人の気持ちの変化・発言の裏にある事情・証拠と決めつけの違いなど、国語読解の力につながる展開を入れる。
- 説教調の長い解説は避ける。間違いや勘違いから、登場人物が自分で気づく構成を優先する。
- 複数の登場人物が性格に応じて話し、衝突・驚き・工夫・解決がある。ナレーターの一方的な講義にしない。
- 不自然な連呼や同じ問答の繰り返しを避ける。音声にしたときのテンポ優先。

## 2. 「耳だけでわかるか」編集者による立ち止まり点検

**台本完成後、音声制作を開始する前に、必ず以下を読者＝小4・小6の視点で確認する。**

1. 画面・イラスト・プリント・字幕を見ずに、誰がどこで何をしているか追えるか。
2. 誰の発言か、4人の声・言い回し・呼びかけで区別できるか。初登場人物には短い紹介を入れる。
3. ひとつ前の場面を忘れても、重要な手がかりや人物の目的を一言で思い出せる工夫があるか。
4. 新語の意味は小4に理解できる短さか。説明そのものに難語を重ねていないか。
5. おとなが説明しなければ理解できない暗黙の前提や長い複文がないか。
6. 子どもが「えっ？」「自分ならどうする？」と反応したくなる山場があるか。
7. すぐ答えを言ってしまわず、子どもが推理・回答する**実際の無音または小さな音楽の間**があるか。
8. 真相に至る手がかりが示され、唐突な解決ではないか。登場人物の気持ちの変化が伝わるか。
9. 騒々しい効果音・強すぎるBGM・速すぎる話し方で言葉が聞こえなくならないか。
10. 次男だけでなく長男が聴いても、推理や言葉の奥行きを楽しめるか。

上の項目に重大な問題があれば「子どもが聴ける仕様」とは判定せず、台本を修正してから合成する。

## 3. 音声演出と「考える時間」

- 目標時間: 原則10〜15分。第1回の12分前後を品質基準とする。尺を稼ぐために内容を薄めない。
- 地の文・主役・相手役・案内役など、聞き分けやすい複数声のVOICEVOXを用いる。各声の性格を急に変えない。
- オリジナルBGM・ジングル・効果音を場面に応じて使用。ナレーションやキーワードを邪魔しない。
- 場面の切替にはジングルや短い音の目印をつけ、急に話題を変えない。
- エピソード中盤に少なくとも1回「いま何がわかっている？」など短い整理を入れる。事実を整理し、謎の答えを先に言わない。
- 物語中に、子どもが推理する**立ち止まりポイント**を原則1〜2回。問いの後、原則4〜7秒程度の回答・思考時間をあける。
- 最後に4〜6問程度の参加型クイズを入れる。各問、選択肢を耳で聞いて理解できる長さにし、答えの前に原則5秒前後の間を設ける。
- 正解発表は理由を短く説明し、誤答をからかわない。
- 難しい固有名詞を連続させず、「言葉の説明」パートが長く続く場合は、会話か出来事を挟む。
- 年齢に不適切な怖さ、過度な罰、個人情報が含まれないようにする。

## 4. MP3完成後の実聴チェック

合成と書き出しに成功しても、すぐに「公開完了」としない。少なくとも冒頭・場面切替・主要語の初出・推理の間・各クイズの解答前後・結末の音を点検する。実際に試聴できるツールがないときは試聴したと偽らず、読み上げ用テキスト検査・音声データ検証までと記録する。

- 読み間違い、発音崩れ、声の取り違え、言い切りの欠落、語頭切れ、過剰な間、突然の大音量がないか。
- 質問の直後に答えが重なっていないか。クイズの間が**MP3の中に実在するか**。
- 音声の長さと章の開始時刻、MP3サイズ、番組名・回数・語彙数・sha256が一致するか。
- 子どもが途中で再開しても話を理解できる章立て・タイトルになっているか。
- 最後にもう一度「小4でも耳だけで楽しめるか」「小6にも推理する価値があるか」「第1回と同じくらい続きが気になるか」を確認する。

## 5. 公開・再生に関する運用

- 既存の「まいにちニュース」「ことわざ事件簿」を変更・削除しない。
- GitHub Pagesは現状有効でないため、公開が確認されない限りPages URLを完成リンクとして案内しない。
- 正常動作が確認できた GitHub Releases の方式を優先し、**各回を固有のタグと固有のMP3**として保存。既存回を上書きしない。
- GitHub Actions が成功、Release に正しいMP3が存在し、回数・サイズを確認できて初めて「公開成功」と報告する。
- AndroidでMP3を直接開いて再生できることがユーザーによって確認済み。今後は直接リンクを優先し、未検証のページを再生ページと呼ばない。
- GitHub Releasesの公開は原則保存期限なし（削除・サービス変更などの例外あり）。必要に応じて手元保存を案内。
- 費用ゼロ、PC操作不要、可能ならユーザーは「第何回・テーマ・作成」と伝えるだけで済む運用を守る。

## 制作前後の最終合格メモ（各回ごとに記録）

- 選定した語彙ID・語句・意味と原稿での使用確認
- 物語の中心の謎・山場・解決理由
- 耳だけの理解テスト：合格／要修正と修正内容
- 4声／音楽／効果音／本編内の推理ポーズ／クイズ回答間の確認
- MP3実体・再生時間・音声ハッシュ・GitHub Actions結果・Releaseアセットの確認
- 実際にスマホで試聴したかどうかを区別して記録

品質が不足する場合は、自動で公開するよりも一度立ち止まり、修正を優先する。
